# Conductor

Kubernetes-native workload residency operator for scarce homelab resources.
Conductor currently protects the two-rank TensorFold lane on the DGX Spark pool;
its API is designed to grow into priority-based control of LLMs, build jobs, and
interactive workloads such as the astrolabe SteamOS/Sunshine gaming pod.

## Architecture

Conductor is now a proper Go operator built with `controller-runtime`:

```text
ResourcePool + ManagedWorkload + WorkloadOverride
                       │
                       ▼
          conductor controller (2 replicas,
              Lease leader election)
                       │ client-go
                       ▼
 Deployments / Pods / Nodes / EndpointSlices / Services
```

The production controller does **not** shell out to `kubectl`. It uses the
projected ServiceAccount token and cluster CA through `client-go`, and its image
contains only a static binary. CI publishes one OCI index for `linux/amd64` and
`linux/arm64`, so the control plane can run on any eligible node.

### API

- **`ResourcePool`** — a contention/failure domain such as `dgx-spark` or a
  future `astrolabe-interactive` pool. It carries management and fencing policy.
- **`ManagedWorkload`** — the permanent GitOps definition. Milestone one uses a
  `DeploymentSet` driver that references existing homelab-owned Deployments and
  encodes ordered start/stop and `RecreateTogether` recovery.
- **`WorkloadOverride`** — temporary, auditable CLI/web intent (`Pin`, `Suspend`,
  `FreezePool`, `Automatic`) with expiry, actor, reason, and idempotency key.
  Overrides are separate from GitOps-owned workload specs.

The baseline `tensorfold-v14` workload is intentionally installed in
**Observe** mode. Observe mode publishes status and Conditions but never changes
replicas. Promotion to **Manage** requires reviewed status/events and a controlled
failure test.

## Recovery contract

Tensor-parallel ranks are one failure domain. Recovery is a persisted,
idempotent state machine:

1. stop head;
2. wait for head to disappear;
3. stop workers;
4. wait for all ranks to disappear;
5. start workers in declared order;
6. wait for each worker;
7. start head;
8. require head readiness and exactly one stable-service endpoint.

Each reconcile performs one bounded action and records the next phase in status.
Controller restarts and leader changes therefore resume instead of replaying a
long imperative transaction. A NotReady/absent node blocks destructive recovery
by default until fencing is proven, avoiding split-brain hostNetwork/GPU work.

## Commands

```bash
# Production operator
conductor controller

# Transitional workstation break-glass CLI (still kubectl-backed)
conductor lane status
conductor lane reconcile --dry-run tensorfold-v14
conductor lane reconcile --yes tensorfold-v14

# Legacy gateway; not deployed while its old swapper is retired
conductor server
```

The direct lane CLI remains for migration and emergencies. Autonomous ownership
requires explicit CRs; naming conventions alone never authorize management.

## Development

```bash
cd scheduler
CGO_ENABLED=0 go test ./...

cd ..
uv run --project generator --extra dev pytest -q generator/tests

# Render the cdk8s control plane
nix run .#generate-manifests
```

Deployables are generated by `generator/main.py`: CRDs, least-privilege RBAC,
two controller replicas, a PDB, and baseline CRs. The obsolete vLLM templates,
LiteLLM router, and Fission watch resources are no longer rendered.
